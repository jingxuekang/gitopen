# getStatistics 云函数测试文档

## 测试概述

本文档描述了 getStatistics 云函数的测试策略和测试用例。该云函数实现了运营数据统计功能，包括每日统计、商品统计、热销排行、地域分布等。

## 测试环境要求

- Node.js >= 14.x
- Jest >= 29.0.0
- wx-server-sdk ~2.6.3

## 运行测试

```bash
# 安装依赖
npm install

# 运行所有测试
npm test

# 运行测试并查看覆盖率
npm test -- --coverage

# 运行特定测试文件
npm test getStatistics.test.js
```

## 测试用例说明

### 1. 每日统计功能测试

#### 测试用例 1.1：正确统计订单数量和销售额
**目的**：验证能够正确统计指定日期范围内的订单数量、销售额和新增用户数

**测试数据**：
- 3个已支付订单，金额分别为 10000、20000、15000 分
- 5个新增用户

**预期结果**：
- orderCount = 3
- totalSales = 45000
- newUserCount = 5

**验证需求**：20.1

#### 测试用例 1.2：处理空订单数据
**目的**：验证在没有订单数据时能够正确返回0值

**测试数据**：空订单列表

**预期结果**：
- orderCount = 0
- totalSales = 0
- newUserCount = 0

#### 测试用例 1.3：使用默认日期范围
**目的**：验证未提供日期参数时使用当天作为默认范围

**预期结果**：
- startDate 为当天0点
- endDate 为当前时间

### 2. 热销商品排行榜功能测试

#### 测试用例 2.1：正确统计商品销售量并排序
**目的**：验证能够正确统计每个商品的销售量和销售额，并按销售量降序排序

**测试数据**：
- 商品1：2个订单，销量15，销售额15000
- 商品2：1个订单，销量3，销售额3000
- 商品3：1个订单，销量2，销售额2000

**预期结果**：
- 排序：商品1 > 商品2 > 商品3
- 商品1：salesCount=15, salesAmount=15000

**验证需求**：20.4

#### 测试用例 2.2：限制返回前20名商品
**目的**：验证当商品数量超过20时，只返回前20名

**测试数据**：25个不同商品

**预期结果**：
- 返回商品数量 <= 20

#### 测试用例 2.3：处理空订单数据
**目的**：验证在没有订单时返回空列表

**预期结果**：
- hotProducts = []

### 3. 用户地域分布统计功能测试

#### 测试用例 3.1：正确统计省份和城市分布
**目的**：验证能够正确统计用户的省份和城市分布，包括订单数、用户数和销售额

**测试数据**：
- 浙江省杭州市：2个订单，2个用户，30000元
- 浙江省宁波市：1个订单，1个用户，15000元
- 江苏省南京市：1个订单，1个用户，30000元

**预期结果**：
- 浙江省：orderCount=3, userCount=2, salesAmount=45000
- 杭州市：orderCount=2, userCount=2, salesAmount=30000

**验证需求**：20.5

#### 测试用例 3.2：按订单数量排序省份和城市
**目的**：验证省份和城市按订单数量降序排序

**测试数据**：
- 浙江省：3个订单
- 江苏省：2个订单

**预期结果**：
- provinceStats[0].province = '浙江省'
- provinceStats[1].province = '江苏省'

#### 测试用例 3.3：处理缺少地址信息的订单
**目的**：验证能够正确处理地址信息缺失的订单

**测试数据**：
- 1个有地址的订单
- 2个无地址的订单

**预期结果**：
- 只统计有地址的订单
- provinceStats.length = 1

#### 测试用例 3.4：限制城市统计返回前50个
**目的**：验证当城市数量超过50时，只返回前50个

**测试数据**：60个不同城市

**预期结果**：
- cityStats.length <= 50

### 4. 商品统计功能测试

#### 测试用例 4.1：处理商品浏览记录表不存在的情况
**目的**：验证当 product_views 表不存在时，浏览量返回0而不是报错

**测试数据**：
- 1个商品
- product_views 表不存在

**预期结果**：
- viewCount = 0

**验证需求**：20.2

### 5. 错误处理测试

#### 测试用例 5.1：处理无效的统计类型
**目的**：验证传入无效统计类型时返回错误

**测试数据**：type = 'invalid'

**预期结果**：
- success = false
- message = '无效的统计类型'

#### 测试用例 5.2：处理数据库查询错误
**目的**：验证数据库查询失败时能够正确处理错误

**测试数据**：模拟数据库错误

**预期结果**：
- success = false
- message = '获取统计数据失败'
- error 包含错误详情

### 6. 综合统计功能测试

#### 测试用例 6.1：返回完整的综合统计数据
**目的**：验证 overview 类型能够返回所有统计数据

**预期结果**：
- data.daily 包含每日统计
- data.hotProducts 包含热销商品（前10名）
- data.region 包含地域分布（前10个省份和城市）
- data.totals 包含总体数据（总用户数、总商品数、总订单数）

## 性能测试建议

1. **大数据量测试**
   - 测试10000+订单的统计性能
   - 测试1000+商品的统计性能
   - 测试100+省份/城市的统计性能

2. **并发测试**
   - 模拟多个管理员同时查询统计数据
   - 验证数据库连接池是否足够

3. **缓存测试**
   - 验证重复查询的性能
   - 测试缓存失效机制

## 集成测试建议

1. **端到端测试**
   - 创建真实订单数据
   - 调用云函数获取统计
   - 验证统计结果的准确性

2. **数据一致性测试**
   - 验证统计数据与实际数据库数据一致
   - 验证不同统计类型之间的数据一致性

## 测试注意事项

1. **时区问题**
   - 确保日期时间使用统一的时区（建议使用UTC）
   - 测试跨天、跨月的统计

2. **数据精度**
   - 金额使用"分"为单位，避免浮点数精度问题
   - 验证大额订单的统计准确性

3. **边界条件**
   - 测试空数据情况
   - 测试单条数据情况
   - 测试大量数据情况

4. **错误恢复**
   - 测试数据库连接失败的情况
   - 测试部分数据查询失败的情况
