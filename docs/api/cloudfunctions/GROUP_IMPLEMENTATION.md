# 拼团功能实现说明

## 任务 15.2 实现内容

本任务实现了拼团功能的核心逻辑，包括：

### 1. 云函数实现

#### createGroup - 发起拼团
- **位置**: `cloudfunctions/createGroup/`
- **功能**: 用户发起一个新的拼团
- **关键逻辑**:
  - 验证拼团活动状态、时间和库存
  - 验证订单是否已支付
  - 检查用户是否重复参与
  - 创建拼团记录并设置过期时间
  - 扣减拼团活动库存
  - 更新订单的拼团信息

#### joinGroup - 参与拼团
- **位置**: `cloudfunctions/joinGroup/`
- **功能**: 用户参与已存在的拼团
- **关键逻辑**:
  - 验证拼团状态（进行中、未过期、未满员）
  - 验证用户是否已参团
  - 验证订单是否已支付
  - 添加成员到拼团
  - 检查是否达到成团人数
  - 如果成团，更新状态并发送通知（TODO）

#### checkExpiredGroups - 检查过期拼团
- **位置**: `cloudfunctions/checkExpiredGroups/`
- **功能**: 定时检查并处理过期的拼团
- **触发器**: 每5分钟执行一次
- **关键逻辑**:
  - 查询所有过期且状态为"拼团中"的记录
  - 更新拼团状态为失败
  - 恢复拼团活动库存
  - 处理所有参团订单的退款
  - 恢复商品库存
  - 退还优惠券
  - 调用微信支付退款接口（TODO）

## 数据流程

### 发起拼团流程
```
1. 用户在拼团活动页选择商品
2. 创建订单并完成支付
3. 调用 createGroup 云函数
4. 创建拼团记录（团长为当前用户）
5. 扣减拼团活动库存
6. 更新订单的拼团信息
7. 返回拼团ID
8. 跳转到拼团详情页
9. 用户可以分享给好友
```

### 参与拼团流程
```
1. 用户通过分享链接进入拼团详情页
2. 查看拼团信息和进度
3. 创建订单并完成支付
4. 调用 joinGroup 云函数
5. 验证拼团状态和用户资格
6. 添加用户到成员列表
7. 检查是否达到成团人数
8. 如果成团，更新状态为成功
9. 发送通知给所有成员（TODO）
10. 刷新页面显示最新状态
```

### 拼团超时处理流程
```
1. 定时任务每5分钟执行一次
2. 查询所有过期且状态为"拼团中"的记录
3. 对每个过期拼团：
   a. 更新拼团状态为失败
   b. 恢复拼团活动库存
   c. 遍历所有参团订单：
      - 更新订单状态为已取消
      - 恢复商品库存
      - 退还优惠券（如果使用了）
      - 调用微信支付退款接口（TODO）
      - 发送退款通知（TODO）
4. 记录处理结果
```

## 关键技术点

### 1. 库存一致性
- 使用数据库的 `_.inc()` 方法原子性地增减库存
- 拼团失败时正确恢复库存
- 考虑并发场景下的库存扣减

### 2. 拼团状态管理
- 状态定义：
  - 0: 拼团中
  - 1: 拼团成功
  - 2: 拼团失败
- 状态转换：
  - 拼团中 → 拼团成功（人数达标）
  - 拼团中 → 拼团失败（超时）

### 3. 过期时间计算
```javascript
const expireAt = new Date(now.getTime() + activity.duration * 60 * 60 * 1000)
```
- 根据活动设置的拼团时长（小时）计算过期时间
- 定时任务检查过期时间并处理

### 4. 拼团进度显示
```javascript
const progressPercent = (group.currentCount / group.requiredCount) * 100
```
- 实时显示当前人数和成团人数
- 进度条动画效果
- 倒计时显示

## 注意事项

1. **定时触发器配置**: 需要在云开发控制台手动配置 checkExpiredGroups 的定时触发器

2. **退款功能**: 当前退款逻辑已实现数据库操作，但微信支付退款接口调用需要后续配置

3. **通知功能**: 拼团成功和退款通知的模板消息需要在微信公众平台配置

4. **订单集成**: 需要在订单创建流程中集成拼团功能，支付成功后自动调用 createGroup 或 joinGroup

5. **性能考虑**: 定时任务处理大量过期拼团时可能影响性能，建议添加批量处理和错误重试机制
